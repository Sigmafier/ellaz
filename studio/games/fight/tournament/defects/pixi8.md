# pixi8 cell - defects log

One line per defect hit while building the PixiJS 8 arm: what it was, and the
class it belongs to. Honest and specific, because this log is a ranking input -
a short log is only worth something if it is short because the engine behaved.

- 2026-09-12 pixi's own spritesheet parser reads a frame's `anchor` (`Spritesheet.js:121 defaultAnchor: data.anchor`); OUR atlas calls that field `pivot`, so `defaultAnchor` comes back undefined and every fighter would have drawn from its TOP-LEFT - a 98 x 100 px offset at draw scale 0.2, on a sheet whose pivot is the feet. Class: a field the vendor ignores because it is under a different name, and nothing raises. Avoided by fetching the atlas json in the cell and setting `anchor.set(frame.pivot.x, frame.pivot.y)` per frame, and by building the `Spritesheet` by hand from the png texture rather than letting `Assets.load` detect it.
- 2026-09-12 `Application.init()` starts the shared ticker, so a cell that only mutates its scene graph still paints at the engine's own rate and the sweep would be comparing a different number of drawn frames per arm. Class: an engine that owns a loop the contract has no method for. Fixed with `app.stop()` at load and one explicit `renderer.render(stage)` in `endFrame` - drawn frames now equal harness frames.
- 2026-09-12 the harness draws `drawBoxes` AFTER `drawHud`, and the HUD must not shake while the boxes must - the same trap the canvas arm logged, but in a scene graph it is a PARENTING decision rather than a save/restore: the box Graphics is a sibling of the hud container on the stage, added after it, carrying the shake offset itself. Class: draw order and transform are one decision in immediate mode and two in retained mode.
- 2026-09-12 `npx vite build --outDir ../../../dist-fight-pixi8` put the tree in `ellaz/dist-fight-pixi8` - one level ABOVE studio, and not where `--dist dist-fight-pixi8` from `studio/` looks. Vite resolves `--outDir` against `config.root`, which this config sets to `games/fight`, while the config's own default is written from `cells/` (`resolve(HERE, "../../../dist-fight")` = `studio/dist-fight`). The two relative paths look identical and have different bases. Class: a relative path whose base is not where the reader assumes. `--outDir ../../dist-fight-pixi8` is the correct flag; nothing in my lane needed changing.
- 2026-09-12 the vite input list is `readdirSync` over `cells/`, so a CONCURRENT lane's half-landed cell breaks every other lane's build: `Could not resolve "./cell" from "phaser4/main.ts"` with `phaser4/` holding only `index.html` and `main.ts`. My build failed for 50 s until the peer's `cell.ts` appeared. Class: a shared input list that mirrors a directory two writers are in. Not fixable inside this lane; a lane cannot build alone.
- 2026-09-12 the phaser4 lane imports `canvas/font.ts`, so the build now emits a shared `font-BL3CuWRA.js` and the canvas bar's authored bytes moved OUT of its own entry chunk (6.67 kB raw before, 5.11 kB + a 1.63 kB shared chunk after). Class: a shared module moving a number the tournament reads. This arm duplicates the 5x7 glyph table into its own `cell.ts` instead, for that reason and because a cell must ship beside its engine alone.
- 2026-09-12 my screenshot harness: "open both arms, wait 2 s, shoot" is NOT the same moment. Measured, the two arms reached tick 124 vs 149 in the same wall second, and a second attempt waiting on `__fightTicks >= 120` from outside overshot to 160 vs 126. The pixel diff taken that way read **5,211 px (2.26%)** and I read a leaning robot and boxes shifted 7 px out of it - all of it the two arms being at different ticks. Tick-matched (rAF replaced with a pumped clock, 1000/60 ms a frame, alpha exactly 0) the same pair reads **21 px**. Class: a differential whose arms were never held equal (`a-diagnostic-that-truncates-what-it-compares`). The instrument now prints the tick beside every shot so a mismatch cannot hide.
- 2026-09-12 and the instrument defect inside that fix: `page.waitForFunction` polls on `requestAnimationFrame` by default, and the init script had just replaced rAF - so the wait timed out for 30 s on a page that was running perfectly. Class: a probe that depends on the thing it is replacing. `polling: 100`.
- 2026-09-12 the ONLY pixels that differ from the bar are fx dots: canvas2d `arc()+fill` is antialiased and a Pixi `circle()` under `antialias: false` is not, so a dust particle's edge is a hard pixel here and a blended one there. Measured tick-matched at six ticks: 30 -> 0 px, 118 -> 24, 120 -> 21, 200 -> 16, 400 -> 0, 599 -> 18, of 230,400. Class: a rasteriser difference in decoration, not a draw-plan difference - every sprite, box, bar and glyph is byte-identical. Left as is: forcing it either way would mean either turning antialias on (which changes what the whole arm is measured at) or reimplementing the bar's circle rasteriser.
