# littlejs cell - defects log

One line per defect hit while building the LittleJS 1.18.29 arm: what it was,
and the class it belongs to. Honest and specific on purpose - this log is a
ranking input, so a defect that cost an hour is worth more here than a tidy
summary. This engine had never run on this machine before today.

## Defects

- 2026-09-12 `engineInit` OVERWRITES `rootElement.style.cssText` with its own string (`margin:0;overflow:hidden;background:#000;...`), so anything a cell writes on its host before init is silently discarded - and because the string carries no `position`, the two canvases it then appends (`position:absolute;top:50%;left:50%;transform:translate(-50%,-50%)`) centre on the VIEWPORT rather than on the host. A cell that passes the harness's `#stage` straight in gets its canvas positioned somewhere else on the page and a black box where the host was. Class: a library writing over the caller's element. Fixed by handing `engineInit` a detached div of my own and styling it AFTER init (`position:relative` is the load-bearing word), then appending that div to the host in `mount`.
- 2026-09-12 `updateCanvas()` rewrites `mainCanvas.style.width/height` and `glCanvas.style.width/height` EVERY frame from `canvasFixedSize`, to `100%`/`''` or `''`/`100%` depending on the window's aspect. So a cell cannot do the canvas bar's integer upscale on the canvas itself - whatever it writes is gone on the next frame. Class: an engine that owns a property the caller also wants to write. Fixed by doing the upscale on the WRAPPER instead, which the engine's `100%` then resolves against; measured 640x360 CSS on both canvases at the harness's 800x600 viewport.
- 2026-09-12 `loadTexture` awaits `image.onerror = image.onload = resolve`, so a 404 sheet RESOLVES and becomes a 1x1 white texture - every fighter would draw as a white slab, with nothing thrown, nothing logged, and the admission gate's error watcher silent. Class: a loader that fails open. Guarded in `adopt()` by comparing `textureInfos[i].size` against the atlas's own `meta.size` and throwing with the URL.
- 2026-09-12 `updateCanvas()` also sets `mainContext.lineJoin = 'round'` and `lineCap = 'round'` on the shared 2D overlay every frame. A round join on a 1px `strokeRect` leaves four partially-covered corner pixels per box, which the canvas bar (default `miter`) does not have. Measured at tick 30: **200 differing px, maxDelta 59 -> 184 px, maxDelta 1** once the cell sets `miter`/`butt` itself. Class: an engine leaving state on a context it shares with the caller. The tell was that every one of the 16 stray pixels was a single isolated dot at a box corner.
- 2026-09-12 `glAntialias` defaults to **true**, so `glCanvas` would come back with MSAA on and `gl.getParameter(gl.SAMPLES)` nonzero while pixi8 and phaser4 both report 0 - the arms would be compared on different pixel work, which is the exact failure `assert-equal-work` exists for. `glSetAntialias(false)` must be called BEFORE `engineInit` (it asserts on `glCanvas` already existing). Class: a default that quietly changes what an arm is measured at.
- 2026-09-12 LittleJS owns a `requestAnimationFrame` loop the contract has no method for: left alone it renders at its own rate and the sweep would compare a different number of drawn frames per arm. Class: an engine that owns a loop the contract has no method for - the same one pixi's ticker and phaser's display list posed. Fixed with `setEngineManualStep(true)` before init and one `engineStep(1)` in `endFrame`, so drawn frames equal harness frames.
- 2026-09-12 the engine's own atlas reader, `parseAtlas`, drops our per-frame `pivot` entirely (it reads `frame`, `spriteSourceSize`, `sourceSize`, `rotated` and nothing else) and then REGROUPS frames by name stem into animations, so `robot_idle_0000` stops being a name you can look up. Same class as the pixi lane's `anchor`-vs-`pivot` finding: a field the vendor ignores because it is under a different name, and nothing raises. Avoided by building one `TileInfo` per frame from our atlas JSON directly and never calling `loadAtlas`/`parseAtlas`.
- 2026-09-12 the engine notes for this lane say `new TileInfo(vec2(fx, fy), vec2(fw, fh), textureIndex)`. The third parameter is a **TextureInfo object**, not an index (`constructor(pos, size, textureInfo, padding, bleed, columns)`); passing a number type-errors, and in JS would have silently produced a tile with no texture. Class: a signature recalled rather than read. `textureInfos[i]` is the object.
- 2026-09-12 `debugWatermark` is **true** in the dev build and `debugRender()` paints an engine/FPS line over the top-right of `mainCanvas` AFTER `gameRenderPost`, i.e. over the HUD. Vite resolves the package's `production` export condition at build time, so the shipped bundle is `littlejs.esm.min.js` and never contains it - but `vite dev` resolves `default`, which is the debug build, so the dev page and the built page would DRAW differently. Class: a dev artifact and a built artifact disagreeing about pixels. `setDebugWatermark(false)` is called unconditionally; it exists in both builds.
- 2026-09-12 the session scratchpad is SHARED by every concurrent cell lane, and a peer's `pixel-compare.mjs` overwrote mine while it was being run - the same shape as the vite input list that `readdirSync`es `cells/` (pixi8's log). Class: a shared directory two writers are in. Moved my instrument into a lane-private subdirectory; not fixable inside a lane.
- 2026-09-12 `soundEnable` defaults true and `audioInit` builds a gain node off the module-level `audioContext` at startup. Not a failure here, but it is work the plain-canvas bar is not doing and the contract asks for none of it. `setSoundEnable(false)` before init, the same call phaser4's `noAudio` makes.
- 2026-09-12 NOT re-paid, because the two prior lanes wrote it down: `--outDir` resolves against the config's **root** (`games/fight`), not the cwd, so the flag from `cells/` is `../../dist-fight-littlejs`. Read from `pixi8.md`/`phaser4.md` before the first build and the tree landed in `studio/` first try.

## Notes a judge should see (decisions, not defects)

- **GL is ON.** pixi8 and phaser4 are WebGL arms; an arm that fell back to Canvas2D would be compared against them on a different pipeline. WebGL2 came up first try headless, `antialias false`, `SAMPLES 0`, `drawingBuffer 640x360` - no fallback was needed and `setGLEnable(false)` is not used anywhere in this cell.
- **TWO canvases, both 640x360.** `glCanvas` (WebGL2) is appended first and carries the arena, the shadows, the fighters and the particles; `mainCanvas` (Canvas2D) sits on top of it and carries the HUD and the `?boxes=1` overlay. That split is LittleJS's own documented architecture ("glCanvas: WebGL canvas for accelerated sprite batch rendering / mainCanvas: Canvas2D overlay for text, UI, and custom drawing"), and it is also what makes the HUD un-shakeable for free - the overlay is not under the camera. A judge reading the timing sweep should know that roughly 200 small HUD rects a frame are Canvas2D on this arm while the ~240 arena rects, both shadows, both fighters and every particle are GL. `document.querySelector("canvas")` finds `glCanvas`, which is also what `stats().backbuffer` reports, so the two agree.
- **The world mapping, and why the shake rides the camera.** `setCameraScale(1)` with the camera at (320, 180) makes one world unit one framebuffer pixel with y UP, so view (vx, vy) is world (vx, 360 - vy) and no coordinate needs a fudge. The screen shake is `setCameraPos(320 - ox, 180 + oy)` rather than an offset added to every draw - a camera is the thing that exists for this, and the HUD being on the un-camera'd overlay means it cannot accidentally inherit it. Proved with `?boxes=1`: the green bdy boxes wrap both fighters from head to feet, the blue push boxes sit at the feet and the red itr box sits on the robot's punching arm - a y-flip mistake would have put them above the head.
- **Flip is `drawTile`'s `mirror` about the PIVOT, not the frame centre.** `drawTile` anchors a tile by its centre, so the centre is the contract's pivot point plus half the drawn frame, and the flip negates that offset. Both sheets happen to have `pivot.x` at the frame's middle, so mirroring about the centre would look identical TODAY and be wrong for the first character whose feet are off-centre.
- **The pivot comes from the MANIFEST, not the atlas frame.** Both carry one and they agree (robot 0.5/0.7576, teddy 0.5/0.7447), which is exactly why a drift would be silent. The bar reads the manifest, so this arm reads the manifest - phaser4's reasoning, adopted.
- **HUD text is the bar's 5x7 bitmap font, painted as `fillRect` glyph rows straight onto `mainContext`**, not `drawTextScreen` (which would be a real typeface, the only thing on screen not on the arena's pixel grid) and not `engineImageFont` (an 8x8 sheet of the engine's own). The glyph table is DUPLICATED into this cell rather than imported from `canvas/font.ts`, for the reason the pixi lane logged: a shared import puts a shared chunk in both arms' byte report and moves a number the tournament is reading. It costs this arm its share of 3,284 gz authored.
- **No text cache.** The bar caches rendered strings to an offscreen canvas and blits; this arm repaints ~140 glyph pixels a frame. That is MORE work than the bar does, not less, so it cannot flatter the arm.
- **The draw plan is kept by reference, never copied.** The harness builds fresh arrays every frame, so `beginFrame` drops the old references and the paint callbacks walk the new ones. A copy would be per-frame work no other arm is doing.
- **`GPU stall due to ReadPixels`** appears four times in the console on this arm under headless swiftshader. It is a driver performance message, not an error, and **pixi8 prints the identical message on the same build** (phaser4 and canvas do not) - so it is a property of compositing a WebGL canvas in this environment, not of this arm. Recorded here so nobody later reads it as one.
- **`LittleJS Engine v1.18.29` is logged to the console at init** and there is no setter to suppress it (`showEngineVersion` is not exported). It is a `console.log`, so the admission gate - which counts `console.error` - is unaffected.

## What the arm measured

- `run-tape --dist dist-fight-littlejs littlejs` - **ADMITTED**, ticks 600, hash `dfd5d033`, chain `2617d8f2`, eventHash `687c23d3`, zero page errors and zero console errors, **first run**.
- `assert-equal-work canvas littlejs` - backbuffer 640x360 both, dpr 1 both, drawn 20 both; littlejs reports `drawingBuffer 640x360`, `samples 0`, `antialias false`, css 640x360. Both of its canvases are 640x360 and both are `image-rendering: pixelated`.
- `bytes` - engine **12,397 gz** (29,041 raw) - shared 10,342 gz - authored 3,284 gz - total 26,023 gz, 4 chunks. The engine column is an order of magnitude under every other arm built so far (kaplay 69,510 - excalibur 124,498 - pixi8 164,029 - phaser4 378,540).
