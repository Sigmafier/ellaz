# phaser4 cell - defects log

One line per defect hit while building the Phaser 4 arm: what it was, and the
class it belongs to. Honest and specific on purpose - this log is a ranking
input, so a defect that cost an hour is worth more here than a tidy summary.

## Defects

- 2026-09-12 `vite build --outDir ../../../dist-fight-phaser4`, run from `cells/`, does NOT land where that path reads from the cwd: vite resolves `outDir` against the config's **root** (`games/fight`), so the tree landed at `ellaz/dist-fight-phaser4` while `run-tape.mjs --dist dist-fight-phaser4` (run from `studio/`) looked at `studio/dist-fight-phaser4` and reported `dist not found`. The correct flag from `cells/` is `--outDir ../../dist-fight-phaser4`. Class: one relative path with two plausible bases, both correct in their own frame. Not mine alone - `ellaz/dist-fight-pixi8` exists too, so the pixi lane split its tree the same way. The stray copy I made was quarantined with `safe-rm`, not `rm`.
- 2026-09-12 `scene.textures.createCanvas(key, ...)` on a key that already exists does not throw and does not return null quietly - `TextureManager.checkKey` emits **`console.error("Texture key already in use")`** and returns null. `run-tape.mjs` counts any `console.error` as a DISQUALIFICATION, so a text cache that simply re-created its texture per frame would have failed admission on a message that is not an exception, is not visible in the page, and is not a rendering fault. Class: a library's soft failure is the harness's hard failure. Fixed by `textures.exists(key)` before every create.
- 2026-09-12 `Sprite.setTexture(key, frame)` in Phaser 4 takes **2** arguments, not the 4 (`updateSize`, `updateOrigin`) that `setFrame` and several sibling classes take - `tsc` reds with TS2554. The consequence is not the type error, it is that a `setTexture` always updates the origin, and Phaser's JSON-hash parser sets `frame.customPivot` from the atlas's own per-frame `pivot` block. So the feet have TWO sources: `<set>.manifest.json`'s `pivot`, and the atlas frame's `pivot`. They agree today (both 0.5 / 0.7576 for robot, 0.5 / 0.7447 for teddy) which is exactly why a drift would be silent. Class: a second source of truth for one fact. Handled by re-applying `setOrigin` from the manifest after every frame change, so the atlas's copy can never be the one that wins.
- 2026-09-12 my first pixel-diff instrument read the arms' pixels with `drawImage(canvas, 0, 0)` into an offscreen 2D canvas inside the page. On the canvas arm that is honest; on a WebGL canvas without `preserveDrawingBuffer` the drawing buffer is **cleared after compositing**, so the read returned a blank image and the diff reported **230,400 of 230,400 px differing (100.000%)** with a bounding box of the whole screen. That reads as a catastrophic arm defect and is entirely a property of the probe. Class: `a-diagnostic-that-truncates-what-it-compares` - an instrument that cannot express the thing it measures. Fixed by diffing compositor SCREENSHOTS (`locator.screenshot()`), which has no such hole. **Every GL arm will meet this**, and a probe written against the canvas bar will pass there and lie on all six others.
- 2026-09-12 the KO-panel probe's first version sampled row `h/2 - 12`, which lands inside the panel's CREAM inset rather than its INK border, and reported `inkRunPx 0, shotsSampled 80` on BOTH arms - runs that had in fact KO'd several times each. Two arms agreeing on a wrong answer reads as a fact about the fight, not about the probe. Class: same family as above; the fix was one row (`round(h/2 - 14) - 4`) and the tell was that a positive control had never been watched firing.
- 2026-09-12 Phaser's display list keeps **insertion** order, so a retained cell cannot get draw order from the sequence of harness calls the way an immediate-mode cell does: `drawBoxes` is called last every frame but its Graphics object was created first, so without depths the boxes render UNDER the fighters and the `?boxes=1` overlay silently stops being an overlay. Class: a retained scene graph remembering a decision the caller re-makes every frame. Fixed with one depth band per harness call (arena 0, shadows 1, sprites 10+, fx 100, hud 200, text 201, boxes 300); sprites take `10 + their position in the already z-sorted call order`, so the plan's own sort is what orders them.

## Notes a judge should see (decisions, not defects)

- **Flip is a negative `scaleX`, not `setFlipX`.** `flipX` mirrors the texture about the frame's CENTRE; the contract says mirror about the PIVOT column. Both sheets happen to have `pivot.x == frameSize.w / 2`, so the two are identical TODAY and a `setFlipX` arm would look correct and be wrong for the first character whose pivot is off-centre. `setScale(-0.2, 0.2)` with the origin at the manifest pivot mirrors about the pivot by construction. Verified with `?boxes=1`.
- **The HUD's bitmap font is imported from the canvas arm** (`../canvas/font`) and baked once per distinct string into a Phaser `CanvasTexture`, rather than re-typing the glyph table. Two copies of a glyph table drift, and the tournament compares arms on the same HUD. It costs the arm 858 B gz in its `authored` column, which is the honest place for it.
- **`scale: { mode: NONE, zoom: 1 }` is load-bearing.** `ScaleManager.updateScale` only writes `canvas.style.width/height` when `_resetZoom` is set, which only happens for `zoom !== 1` - so at zoom 1 the cell is free to do the canvas arm's integer upscaling itself and the two arms size identically. Any other zoom and Phaser and the cell would both be writing the same two properties.
- **`input: false`, `audio: { noAudio: true }`, `banner: false`, no physics.** Every default Phaser boots is work the plain-canvas bar is not doing, and the contract asks for none of them. The banner is also the only thing Phaser writes to the console unasked.
- 2026-09-12 inherited from `canvas.md`: the KO panel (`phase >= 2`) is UNREACHABLE from the golden tape, which ends `winner: -1`. Exercised the same way the bar did - a 6 hp teddy served through `page.route`, at REAL time, because `?fast=1` steps 60 ticks per drawn frame and `koFadeTicks` is 60. Both arms drew `KO  ROBOT WINS` in the same place; screenshots in the lane's scratchpad.
