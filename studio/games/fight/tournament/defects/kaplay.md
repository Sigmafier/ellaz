# kaplay cell - defects log

One line per defect hit while building the KAPLAY 3001 arm: what it was, and
the class it belongs to. Honest and specific, because this log is a ranking
input - a short log is only worth something if it is short because the engine
behaved. Where a line says "read, not run", it was found by reading kaplay's
own source rather than by being bitten, and it says so.

## Defects

- 2026-09-12 **`k.loadSpriteAtlas` computes every frame's UVs against the CONSTANT `SPRITE_ATLAS_WIDTH/HEIGHT` (2048), not against the texture it just loaded.** `assets/spriteAtlas.ts` does `const w = SPRITE_ATLAS_WIDTH * quad.w`, which is exactly the image width while the image fits kaplay's own packer - and is 2048 the moment it does NOT, because an oversized image goes through `TexPacker.addSingle` and comes back `quad(0,0,1,1)`. Our sheets are 4900x3300. Measured against the real robot sheet (`scratchpad/atlas-probe.mjs`, both loaders in one page): the frame at x 980 w 980 came back as **x 2344.7 w 2344.7** - a 2.4x-too-large slab from the wrong part of the sheet, with no error, no warning and a perfectly loaded texture. Class: a library constant standing in for a measured value; correct for the case its author had, silently wrong for a bigger one. The engine notes and kaplay's own docs both recommend this call. Avoided by `k.loadSprite(set, png, { frames: Quad[] })`, whose `SpriteData.fromImage` multiplies by the REAL quad - same probe, same page: **x 980.0 w 980.0**.
- 2026-09-12 **KAPLAY owns its `requestAnimationFrame` loop and exposes no stop/render pair, so the cell paints the plan the harness recorded one frame EARLIER.** `app.run` calls `frame(0)` synchronously inside `kaplay()` - which the harness awaits inside `load()` - so kaplay's callback is queued before the harness's and stays there, both re-registering from inside their own callbacks. pixi took the paint back with `app.stop()` + an explicit `renderer.render`; kaplay has no equivalent (`quit()` destroys, `debug.paused` still draws). Measured tick-matched against the bar at tick 120, two builds from one tree: **2,483 px of 230,400 differing (1.078%) with the loop left in its natural order, 261 px (0.113%) with it deferred**. Class: an engine that owns a loop the contract has no method for, with no public way to hand it back. Fixed by holding kaplay's first rAF registration (a temporary `window.requestAnimationFrame` wrapper around `kaplay()`) and re-issuing it from the first `endFrame` through a `setTimeout(0)`, which lands after the harness has queued its own next frame; from then on the order is [harness, kaplay] and the paint is in the frame that recorded the plan. **The phaser4 arm has the same shape and its log does not carry this**, because it compared at tick 600 where the tape is over and consecutive frames are identical - a lag of one frame cannot show at a standstill.
- 2026-09-12 **`k.rgb("#abc")` THROWS.** `Color.fromHex` matches `^#?([a-f\d]{2}){3}$` and throws `Invalid hex color format` on anything else - no 3-digit form, no 8-digit alpha, no `rgba()`, all of which a 2D context's `fillStyle` accepts silently. Hit while writing the atlas probe (`background: "#000"`), not in the cell, because every colour the cell receives today comes from `shared/arena.ts`'s palette and `shared/fx.ts`'s two constants and all of them are 6-digit. Class: a stricter parser behind an interface the bar's is permissive about - a future palette entry written `#fff` would raise inside `onDraw`, become one of kaplay's own `console.error`s, and disqualify the arm on a message that does not name the colour. The cell now checks and throws naming it, once per distinct colour.
- 2026-09-12 **`loadingScreen: false` does not suppress the loading screen on the first frame.** The run loop reads `if (!assets.loaded && gopt.loadingScreen !== false || isFirstFrame)`, and `&&` binds tighter than `||`, so the first frame always takes that branch and paints a full-screen black rect. Measured: at tick 1 - kaplay's first painted frame - the arm differs from the bar by **230,400 of 230,400 px (100.000%), maxChannel 255**; at tick 2 it is back to 141 px at maxChannel 1. Class: an option whose name describes a condition the code ORs past. Harmless here (one frame, before anything reads pixels) and logged because a screenshot harness that shot the first frame would read it as a dead arm.
- 2026-09-12 **`Asset` is thenable but only ever settles on SUCCESS** - `then(action)` is `onLoad(action)`, and the constructor's failure path re-`throw`s inside a promise chain when nobody has registered an error listener. So `await k.loadSprite(...)` resolves when the sheet loads and hangs forever when it 404s, with an unhandled rejection as the only trace. Read, not run. Class: a promise-shaped object that is not a promise. The cell awaits through an explicit `new Promise((res, rej) => { a.onLoad(res); a.onError(rej); })`, which also suppresses the re-throw.
- 2026-09-12 **The cell cannot ask for the same GL context the other arms get.** kaplay hard-codes `getContext("webgl", { antialias: true, depth: true, stencil: true, preserveDrawingBuffer: true })` with no option, so `assert-equal-work` prints `samples 4, antialias true` for this arm beside `0 / false` for pixi8 and phaser4. It does not change the pixels - kaplay renders the whole scene into a non-multisampled framebuffer and blits that to the backbuffer, so the MSAA applies only to one screen-aligned quad; the evidence is that at tick 30 **every** differing pixel against the bar is a ±1 rounding and the fx circles are visibly hard-edged. Class: an engine that does not let a cell ask for equal work, on an axis the gate reports but does not fail. Logged rather than fixed: the only lever would be patching the context request.
- 2026-09-12 **my own instrument, and it cost the first reading:** the pixel-compare script started pumping its fake clock as soon as `window.__pump` existed, which is before the page has finished fetching its data - **81 of the canvas arm's first 160 pumps drove an empty rAF queue**, so the two arms were at tick 77 and tick 120 when they were shot and the diff read **5,532 px (2.401%)** of engine difference that was entirely the harness. Class: `a-diagnostic-that-truncates-what-it-compares` - an instrument whose arms were never held equal, the same family the pixi lane logged from the other end. Fixed by waiting on `window.__fightTicks !== undefined` (the harness publishes it in the same breath as it queues its first frame) and by advancing the pumped clock by `1000/60 + 1e-9`, so a dt one float-ulp short of the step cannot silently drop a tick and leave the arm interpolating at the moment it is shot. The script prints both arms' tick beside every shot and warns when they disagree.

## Not a defect - a reading with its control

- 2026-09-12 a full tape run logs **four `console.warning`s**: `GL Driver Message (OpenGL, Performance, ...): GPU stall due to ReadPixels`. They are warnings, not errors, so admission is unaffected - and the control says they are not kaplay's: **pixi8 and phaser4, probed from this same built tree, emit the identical four**. The canvas arm emits none, because it has no GL context. Environment, not arm.

## Notes a judge should see (decisions, not defects)

- **The anchor mapping, and it is proven rather than argued.** KAPLAY's anchor is a centre-based `vec2` in -1..1, so a 0..1 pivot fraction `p` maps to `2p - 1`; reading `drawUVQuad` confirms it (`offset = anchor * (w,h) * -0.5`, then the quad spans ±w/2, so the point at texture fraction `(a+1)/2` lands on `pos`). The proof is the `?boxes=1` overlay: at tick 120 the green bdy, red itr and blue push rectangles sit on both fighters **pixel-identically to the canvas bar** - they are not in the diff at all at any of the four ticks whose clusters were dumped (30, 60, 120, 200), and ticks 30 and 60 carry no difference anywhere above ±1.
- **Flip is a negative x scale, not `flipX`.** KAPLAY's `flipX` swaps the quad's uvs and leaves the geometry where it is, so it mirrors about the frame's CENTRE while the contract says mirror about the PIVOT column. Both sheets have `pivot.x == frameSize.w / 2` today, so the two are identical now and a `flipX` arm would be correct by luck and wrong for the first character drawn off-centre. `scale: vec2(-0.2, 0.2)` mirrors about the pivot by construction, because the anchor offset is applied INSIDE the scale.
- **The pivot comes from the manifest, never the atlas.** The atlas carries a per-frame `pivot` too and the two agree today (0.5 / 0.7576 for robot); one of them has to be the source of truth, and the bar's is `manifest.pivot`, so it is this arm's as well - the same call the phaser lane made, for the same reason.
- **The HUD font is a baked glyph SHEET, not `k.drawText`.** All 46 glyphs of the demo brawler's 5x7 table are painted white into one 230x7 canvas at load and loaded as a sprite with one frame per glyph, so a line of text is one `drawSprite` per character at integer scale - pixel-identical to the bar's cached text image (the HUD is not in the diff at any tick). `k.drawText` would have drawn kaplay's own font. The glyph table is duplicated into this cell rather than imported from `canvas/font.ts` for the reason the pixi lane logged: a second importer makes the build emit a shared chunk and MOVES the canvas bar's authored byte count, which the tournament reads.
- **`drawn` counts contract `drawSprite` calls only** - 20 over the tape, equal to the bar. The glyph quads are not sprites the harness asked for and are not counted as such.
- **Boxes are four 1px rects, not a stroked rect.** The bar's `strokeRect(x+0.5, y+0.5, w-1, h-1)` at `lineWidth 1` covers exactly the outline's pixel columns; four rects reproduce that set by construction rather than depending on how kaplay's line joins round. Boxes are off in the tape run and in the timing sweep, so the extra calls cost the arm nothing where it is measured.
- **`focus: false`, `debug: false`, `touchToMouse: false`, `letterbox: false`, `texFilter: "nearest"`, `pixelDensity: 1`.** `debug: false` skips `drawDebug()` and the F1/F2/F7/F8/F9 key handlers every frame; the rest are defaults the plain-canvas bar is not paying for. `width` + `height` with neither `stretch` nor `letterbox` is what makes kaplay take the `fixedSize` branch and set `canvas.width = 640` - the round-3 backbuffer trap (`offsetWidth * pixelDensity`) is the OTHER branch, and `initEvents`' resize handler returns early for the same reason.
- **The KO panel (`phase >= 2`) is UNREACHABLE from the golden tape**, which ends `winner: -1`, so nothing in the verified run draws it - inherited from `canvas.md` and true of every arm. Not exercised in this lane.
